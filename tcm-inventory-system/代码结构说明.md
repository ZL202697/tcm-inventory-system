**登录态管理：**
- 使用 `sessionStorage` 存储：`current_user`, `current_role`, `current_name`
- 每个页面加载时检查登录态，未登录跳转 `index.html`
- API请求自动携带请求头 `X-User: <用户名>`

**统一API封装（每个页面都有）：**
```javascript
const API_BASE = '';
async function api(method, url, body) {
  const opts = {
    method,
    headers: {
      'Content-Type': 'application/json',
      'X-User': sessionStorage.getItem('current_user') || ''
    }
  };
  if (body !== undefined) opts.body = JSON.stringify(body);
  const resp = await fetch(API_BASE + url, opts);
  const result = await resp.json().catch(() => ({code: -1, message: '服务器连接失败'}));
  if (result.code !== 0) { alert(result.message); throw new Error(result.message); }
  return result.data;
}
```

**权限控制：**
- 侧边栏菜单项通过 `data-role` 属性控制显示
- 按钮通过 JS 判断 `currentRole` 控制显示/隐藏
- 后端也做了权限校验（双重保障）

### 3.3 db.py（数据库抽象层）详解

**核心设计：智能双模式**

```
应用代码（app.py）
    │
    ▼ 调用 query() / execute()
┌─────────────────────┐
│   db.py 抽象层       │
│  - 自动识别数据库类型 │
│  - 自动转换占位符    │
│  - 统一返回字典格式  │
└────────┬────────────┘
         │
    ┌────┴────┐
    ▼         ▼
  SQLite     MySQL
 （默认）    （可选）
```

**关键技术点：**
1. **模式切换**：通过环境变量 `USE_MYSQL` 控制，默认SQLite
2. **占位符自动转换**：MySQL用 `%s`，SQLite用 `?`，`_convert_placeholders()` 自动处理
3. **SQLite字典游标**：`DictCursorSqlite` 类包装原生游标，使SQLite返回字典格式（与MySQL DictCursor一致）
4. **统一接口**：`query(sql, args, one)` 和 `execute(sql, args)`，上层代码无需关心底层数据库

### 3.4 init_db.py（数据库初始化）详解

**执行流程：**
1. 检测数据库模式（SQLite/MySQL）
2. 创建5张表 + 4个索引
3. 写入3个默认账号（admin/doctor/doctor2）
4. 写入10种示例药材
5. 写入4张示例处方（覆盖4种状态）+ 17条处方明细
6. 打印完成信息

**幂等设计：**
- 建表使用 `CREATE TABLE IF NOT EXISTS`
- 插入数据前先查询是否已存在，存在则跳过或更新
- 重复运行不会产生重复数据

## 六、关键技术点总结

### 6.1 前后端分离
- 前端纯HTML/JS，通过 `fetch` 调用后端REST API
- 后端Flask托管前端静态文件，统一端口5000，无跨域问题

### 6.2 数据库抽象层
- 智能双模式（SQLite/MySQL），上层代码零改动
- 占位符自动转换，字典格式统一返回

### 6.3 处方业务闭环
- 开具 → 审核 → 发药 → 库存扣减，全流程贯通
- 发药时自动遍历处方明细，逐味扣减药材库存
- 状态机控制：只有已审核的处方才能发药

### 6.4 细粒度权限控制
- 前端：菜单和按钮级别的显示/隐藏
- 后端：每个API都有权限校验装饰器
- 双重保障，防止越权操作

### 6.5 数据可视化
- ECharts 6大图表，覆盖趋势、分布、排行、漏斗等多种分析维度
- 双Y轴图表同时展示数量和金额
- 窗口resize自适应
